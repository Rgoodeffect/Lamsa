# تقرير رفع المنتجات الأولى — متجر لمسة

بيئة التشغيل: موقع تجريبي `lamsa.local` على ERPNext v16 (Frappe 16.35 / ERPNext 16.36)،
منفصل تماماً عن مشروع السيراميك (قاعدة بيانات مستقلة).

## ١. الملفات التي أُنشئت أو عُدّلت

| الملف | الغرض |
|---|---|
| `data/products.seed.json` | بيانات المنتجات الستة (تُعدَّل بسهولة دون كود) |
| `data/product-images/<sku>/` | مجلد صور كل منتج (به الصورة المؤقتة الآن) |
| `store_core/setup/seed_plan.py` | طبقة التخطيط (خالية من frappe، تشغّل `--dry-run` وتُختبر بلا سيرفر) |
| `store_core/setup/seed_products.py` | طبقة التنفيذ (upsert للتصنيفات والأصناف والأسعار والمخزون والحزم والصور) |
| `store_core/setup/seed_images.py` | مولّد الصور المؤقتة المصمّمة |
| `store_core/setup/custom_fields.py` | **migration**: أضاف ٤ حقول (انظر القسم ٤) |
| `store_core/services/catalog.py`, `api/v1/catalog.py` | عرض الوصف المختصر على صفحة المنتج |
| `store_core/tests/unit/test_seed_plan.py` | ٣٣ اختباراً لقواعد الرفع (كلها تنجح) |

## ٢. أوامر التشغيل

على السيرفر، بمستخدم `frappe`، من `~/frappe-bench-v16`:

```bash
# معاينة دون كتابة (شغّليه أولاً دائماً)
bench --site lamsa.local execute store_core.setup.seed_products.run --kwargs "{'dry_run': True}"

# التنفيذ الفعلي (idempotent — آمن لإعادة التشغيل)
bench --site lamsa.local execute store_core.setup.seed_products.run
```

النتيجة الفعلية: `applied: create=33, stock=12, bundle=1, image=6, add value=10`
— أي ٤ تصنيفات، ١٦ صنفاً (٦ منتجات + ١٠ متغيرات)، ١٣ سعراً، ١٣ حركة مخزون، حزمة واحدة، ٦ صور.

السكربت **قابل لإعادة التشغيل**: يعمل upsert حسب الـSKU، والمخزون يُضاف بالنقص فقط
(الهدف − الحالي)، فلا يتضاعف شيء إذا شُغّل مرتين.

## ٣. حالة المخزون والنشر

- الطلب المسبق (pre-order) **غير مدعوم** في المتجر حالياً، لذا رُفعت المنتجات أولاً **كمسودة**.
- بناءً على طلبك لاحقاً، **نُشرت الستة الآن** وظهرت في المتجر بمخزونها الحقيقي.
- **تنبيه:** المنتجات الآن **قابلة للشراء فوراً** رغم أن البضاعة تصل خلال ٢-٣ أسابيع.
- لإرجاع منتج إلى مسودة: افتحيه في لوحة المدير → تبويب *Lamsa* → أزيلي علامة *Publish in Store*.

## ٤. الحقول التي احتاجت migration (نُفّذت)

أربعة حقول لم تكن موجودة في ERPNext، أُضيفت في `custom_fields.py`:

| الحقل | النوع | يظهر للزبونة؟ |
|---|---|---|
| `lamsa_name_en` | Data | نعم (للبحث والفواتير؛ الزبونة ترى الاسم العربي دائماً) |
| `lamsa_short_description_ar` | Small Text | نعم (سطر تحت اسم المنتج) |
| `lamsa_cost_usd` | Float — **permlevel 1** | **لا — داخلي فقط** |
| `lamsa_supplier_url` | Data — **permlevel 1** | **لا — داخلي فقط** |

**حماية التكلفة والمورد (ثلاث طبقات):**
1. `permlevel 1`: لا يقرأهما أي دور بلا صلاحية مستوى-1 على الصنف.
2. مستخدم API للمتجر لا يملك أي صلاحية على DocType الصنف إطلاقاً.
3. كل واجهات المتجر تُصدِّر حقولاً محدّدة بالاسم ولا تمرّر الصنف كاملاً.

**تحقّق فعلي:** فُحصت استجابة API المنتج العامة عن الكلمات `2.6`, `cost`, `alibaba`,
`supplier`, `valuation` — **صفر تسريب**.

حقل `note_internal` (لقطع الزركون) حُفظ كتعليق داخلي على الصنف، بلا migration.
حقول `supplier` و`weight_g` و`tags` استُخدمت حقول ERPNext القياسية.

## ٥. صندوق الهدية

نُفّذ كـ **Product Bundle** (باختيارك): الصندوق نفسه غير مخزني، ومخزونه الحقيقي = أقل مكوّن.
عند بيعه، يخصم ERPNext من الطقم (`LAM-JWL-SET-001`) والزركون (`LAM-JWL-ZRC-001`) تلقائياً.
رقم `stock: 15` في البيانات لم يُطبَّق على الحزمة (ERPNext يحجز مخزون المكوّنات لا الحزمة).
تحذير هذا التعارض ظهر تلقائياً في الرفع.

## ٦. الصور — الحالة وطريقة الاستبدال

**لم تُزوّدي بصور حقيقية** (البيانات تضمّنت روابط موردين فقط، ومنعتِ التحميل منها).
لذا أُنشئت **صورة مؤقتة مصمّمة لكل منتج**: خلفية `#7A3E65`، اسم المنتج بالعربي، وكلمة «لمسة».
وهي مرفوعة ومربوطة كصورة رئيسية.

**لاستبدالها بصورك الحقيقية** (سهل جداً):
1. ضعي صورك في مجلد المنتج: `data/product-images/<SKU>/`
2. سمّي الرئيسية `main.jpg`، والإضافية `2.jpg` ثم `3.jpg` …
3. أعيدي تشغيل السكربت: `bench --site lamsa.local execute store_core.setup.seed_products.run`
4. يعيد ربط `main.*` تلقائياً بدل المؤقتة (السكربت يفضّل الصور الحقيقية على المؤقتة).

مثال: `data/product-images/LAM-WMN-PJ-001/main.jpg` يصبح صورة البيجامة الرئيسية.

## ٧. الأسعار

نهائية بالدينار الليبي كما زوّدتِها (١٦٥، ٩٥، ١٣٠، ٢١٠، ١٨٠، ١٨٠)، بلا أي خصم مُضاف.
المتغيرات تحمل السعر (ERPNext v16 لا يسمح بسعر على القالب). التوصيل يُحسب منفصلاً حسب المنطقة.

## ٨. ما لم يُرفع ولماذا

- **الطلب المسبق**: غير مدعوم في المتجر؛ ميزة منفصلة إن أردتِها لاحقاً.
- **صور حقيقية**: لم تُزوَّد؛ الحالية مؤقتة (انظر القسم ٦).
